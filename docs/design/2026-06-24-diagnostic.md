# Numa design & style diagnostic — 2026-06-24

Multi-agent design critique (6 lenses), grounded in the real tokens/components. Average ~5.7/10: strong, well-engineered foundation (the 3D coin, motion system, tokenised palette) that is **under-spent** — the brand assets exist but the lime accent + coin are not deployed where they would make Numa memorable.

**Shipped in this pass (v0.9.7):** the 3D coin is now the persistent Sidebar logo (was a flat PNG); the route loader spins the coin; ‘Goal reached’ flips a coin (was a flat gray pill); dark-mode --color-ink-4 raised to AA. Welcome A/B (coin vs orb) + tagline → “Track money.” landed alongside.

## 5/10 — brand-memorability

The coin is a genuinely beautiful, well-engineered brand object — real CSS-3D, fully tokenized (--color-coin-*), with spin/float/flip modes ready to reuse — but it is barely deployed. It appears in only four places (welcome hero, onboarding pot, a 32px loader, two incidental flat coins), while the mark users actually see every session is a static raster PNG in the Sidebar. Worse, the highest-emotion moment in the whole app — "Goal reached" in GoalsPage — is a flat gray "Done" pill with no coin anywhere near it. The lime that's supposed to be the brand's loud signature is structurally demoted: in Citrus, --color-brand is near-black (#0f0f08) and the lime only survives as button-text ink. The assets to be memorable exist; the app just doesn't spend them where it counts.

## 5/10 — type-hierarchy

Numa has the right typographic *ideas* — a tabular-num money treatment (.nm-num with slashed-zero), a memorable Geist-Mono-uppercase eyebrow idiom, and DM Sans for display numbers — but the system is not enforced. The named scale tokens (--text-h1, --text-display, --text-caption, etc.) have literally zero usages; every size is a hand-typed text-[NNpx] across 38 distinct values, with 9 tracking values and inconsistent bold/semibold for the very numbers that are supposed to be the brand. The result reads as "tasteful component-by-component" rather than "tight, remembered system," which undercuts the founder's goal of memorability through type taste.

**Strengths:** Money typography foundation is genuinely good: .nm-num (font-variant-numeric: tabular-nums slashed-zero + tnum/lnum) plus DM Sans display for hero amounts is legible and on-brand; The Geist-Mono-uppercase eyebrow/label idiom is a distinctive, ownable signature that differentiates from Monzo/Revolut flat-sans sameness; Each palette theme thoughtfully swaps its display stack (DM Sans/Inter Tight/Newsreader/Geist), showing real type intent per brand mood; iOS 16px-input-min guard in global.css and font-feature-settings ss01/cv11 globally show care about real rendering details

**Moves:**

- [high/l] **Make the scale tokens real and adopt them — they are currently dead code** — _src/styles/tokens.css lines 19-27 (--text-micro…--text-hero); all src/routes/**/page.tsx_
  The 9 --text-* tokens have ZERO usages — every size is a raw text-[NNpx] (38 distinct values incl. text-[9.5px], text-[10.5px], text-[14.5px], text-[7px]). Expose them as Tailwind utilities (text-caption, text-h1, text-display via @theme --text-*) and codemod the dominant clusters: the 183× text-[13px] + 183× text-[12px] → text-caption, 103× text-[14px]→text-body, 104× text-[11px]→text-micro. Add an ESLint/grep guard banning new text-[NNpx]. This collapses 38 sizes to ~9 and is the single highest-impact move for a 'remembered system.'
- [high/m] **Tokenize the mono-eyebrow into one component/class and kill the 102 ad-hoc copies** — _.nm-eyebrow in src/styles/global.css:189; ~102 inline 'font-mono … uppercase tracking-[…]' instances_
  The eyebrow idiom is authored ad-hoc 102× vs only 27 uses of .nm-eyebrow, with 9 different tracking values (0.06–0.22em) and 6 sizes (8.5–11px) for one conceptual style. Standardize .nm-eyebrow to font-mono, 11px, tracking 0.16em, uppercase, ink-3 (the most common real-world values), add a tighter .nm-eyebrow-sm (10px) variant, and replace the inline copies.   Big hero amounts (40px+) split 15× font-bold vs 11× font-semibold with no rule, so the same conceptual element (the money number) renders at different weights across home/money/wealth. Define one display-number weight (recommend font-semibold for DM Sans at large sizes — bold gets heavy) and one tracking (the hero numbers already vary -0.05/-0.055/-0.065em). Bake into a NumaAmount/AmountDisplay component so every surface's primary number is identical.

  Right now big amounts use DM Sans (font-display) while small inline amounts use Geist Mono — a defensible split, but it's implicit and per-file. Create a single <Amount size> component that encodes the rule (display+tabular for hero, mono+tabular for inline/list) plus the leading-[0.9] and tracking. This guarantees the distinctive money treatment is identical everywhere and lets you tune the whole brand's numeric voice in one place.
- [medium/s] **Trim critical-path font loading to the active theme** — _index.html font CSS link (DM Sans+DM Mono+Geist+Geist Mono+Inter Tight+Newsreader on one request)_

## 6/10 — color-darkmode

Contrast hygiene is genuinely strong — Citrus passes AA across nearly every ink/surface pair (ink-4 included), and the tokens carry real, documented AA work. The problem is boldness asymmetry: Citrus DARK makes the lime a loud fill (lime heroes, lime FABs, lime CTAs) and is striking, but Citrus LIGHT demotes the same lime to text-on-black plus near-white brand-soft/mist washes, so the default light mode reads as near-black + cream + faint celery — tasteful but monochrome, not the "bright + memorable" the brand wants. The signature color is louder in dark than in light, which is backwards for a light-first app.

**Strengths:** Contrast discipline is real: in Citrus, lime cta-ink on near-black hero = 13.2:1, ink-4 on white = 4.54, ink-3 = 5.24, dark ink-4 = 4.72-5.38 — all pass AA with documented rationale in tokens.css comments.; Citrus DARK is the standout: --color-cta/--color-brand become saturated lime #d4fa42, driving lime hero panels, lime FAB (home:1135), lime primary buttons — dark mode is more vivid and on-brand than most fintech dark themes.; The coin palette (--color-coin-lime/mid/gold/deep) and the dark-aware .nm-welcome-orb gradient are the one place saturated lime lives consistently in both modes — a strong, ownable brand anchor.; Status + chart palettes are properly forked for dark (brighter chart-1..8, warning #e6b853 at 9:1) so data viz stays legible on the dark canvas.

Keep the black hero for the balance number (its 13:1 lime-on-black is the brand's best moment), but stop letting black be the ONLY fill. Today light mode is perceptually monochrome.

## 6/10 — density-mobile

The bones are good: a real spacing token scale exists, safe-area insets are handled everywhere, the Light-mode bottom nav with its inset FAB is genuinely confident and thumb-friendly, and card padding scales sensibly (px-4 sm:px-6). But the surface-level execution undercuts the "calm, taste-forward" goal in two concrete ways — a radius vocabulary that has quietly sprawled to ~19 different corner sizes (122 arbitrary px values fighting the 5 radius tokens), and a mobile floating-chrome layer that stacks three separate fixed clusters plus double bottom-padding. It reads slightly fussy and inconsistent up close rather than super-simple.

**Strengths:** Safe-area is handled correctly and consistently — pb-[max(env(safe-area-inset-bottom),12px)] on every bottom nav, and FAB clusters offset from env(safe-area-inset-bottom). ## 6.5/10 — motion-delight

The motion *foundation* is genuinely strong and tasteful: motion.ts collapses a sprawl of durations/easings into one named vocabulary (EASE_OUT/POP/LUX/DRAW, DUR tiers) mirrored by CSS tokens, reduced-motion is handled everywhere (global MotionConfig + per-keyframe @media guards on coin, orbs, charts, emoji, Siri ring), and the chart draw-on, route morphs, and AnimatedAmount count-up show real craft. But it's an infrastructure-rich, payoff-poor system: the delight is concentrated in *ambient* moments (welcome orb, loaders, idle coin float) while the *earned* moments — completing a goal, settling a pot, logging an expense, hitting a streak — get almost nothing. The signature asset, the 3D coin, ships a `flip` reward mode that is used in zero places. Numa currently feels polished and calm, not alive and rewarding.

**Strengths:** Real motion language, not vibes: motion.ts is a single source of truth (EASE_OUT/POP/LUX/DRAW + DUR tiers) and is faithfully mirrored in tokens.css (--ease-* / --duration-*), so framer and CSS speak the same dialect.; Reduced-motion safety is exemplary and consistent — global <MotionConfig reducedMotion="user"> plus dedicated @media (prefers-reduced-motion) overrides on every bespoke keyframe (nm-coin3d, nm-orb, nm-chart-draw, nm-emoji, nm-siri-ring, nm-ready-*, view-transitions).
